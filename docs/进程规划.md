## 第一阶段：Spring Boot 做“母体”

你的博客核心后端，我推荐直接：

> **Spring Boot 作为主后端。**

原因不是 Java 一定比 Go 好，而是技术博客这种项目非常适合拿 Spring 练完整企业后端能力。

你可以完整覆盖：

```
用户
登录
JWT
OAuth2
RBAC

文章
标签
分类
评论
点赞
收藏
关注

文件
图片
附件

后台管理

审计日志

数据库事务

缓存

消息队列

定时任务

搜索

监控
```

技术：

```
Java 21+
Spring Boot
Spring Security
Spring Data JPA / MyBatis
PostgreSQL
Redis
Kafka / RabbitMQ
MinIO / S3
```

项目结构一开始甚至不要搞微服务。

建议：

```
blog-server
│
├── auth
├── user
├── article
├── comment
├── taxonomy
├── file
├── search
├── notification
├── admin
├── ai
└── common
```

做成：

> **模块化单体 Modular Monolith**

这是我特别建议你的地方。

很多人学完微服务以后，一做项目就：

```
user-service
article-service
comment-service
auth-service
file-service
...
```

最后大量时间都消耗在：

```
Docker
RPC
注册中心
配置中心
网络
部署
联调
```

反而业务没做多少。

先把 Spring Boot 单体做到真正复杂。

# 第二阶段：把 Go 加进来

项目稳定以后，不要重新写一套 Go Blog。

这样没意义：

```
Java Blog
Go Blog
```

你应该找一个**适合 Go 的模块**拆出去。

例如：

### ① 实时通知服务

```
Spring Boot
    │
 Kafka
    │
    ▼
Go Notification Service
    │
WebSocket / SSE
    │
用户
```

处理：

```
新评论
点赞
关注
系统通知
AI任务进度
在线状态
```

这特别适合 Go：

```
goroutine
channel
WebSocket
高并发
Kafka
Redis Pub/Sub
```

------

### ② 图片/文件处理服务

例如：

```
用户上传图片
      ↓
Spring Boot
      ↓
Kafka
      ↓
Go Worker
      ↓
压缩
缩略图
WebP
元数据
      ↓
MinIO
```

练：

```
Worker Pool
Goroutine
Queue
Context
并发控制
限流
```

这比“用 Go 再写一次 CRUD”有价值多了。

### ③ API Gateway

练：

```

```

```
   ▼
Markdown
   │

   │

   │
   ▼
pgvector
```

查询：

```

   ↓

   ↓
Embedding
   ↓
Vector Search
   ↓
相关文章

答案 + 引用
```

比如文章自动生成：

```

摘要
SEO
标签
知识图谱
相关文章
```

# 第五阶段：把博客升级成 Agent

这个阶段会非常有意思。

你的 AI Assistant 不只是：

```
问问题 → 回答
```

而是：

```
Agent
 │
 ├─ 搜索文章
 ├─ 查询数据库
 ├─ 查询 GitHub
 ├─ 创建草稿
 ├─ 修改文章
 ├─ 生成摘要
 ├─ 生成标签
 ├─ 查询访问数据
 └─ 查询系统状态
```

然后引入：

```
Tool Calling
MCP
Agent
Memory
Human in the loop
```

比如：

> “找出最近半年访问量低于 100 的 Go 文章，给我一个优化建议。”

Agent：

```
调用 analytics tool
      ↓
查数据库
      ↓
调用 article tool
      ↓
读取文章
      ↓
LLM 分析
      ↓
生成优化方案
```

这已经非常接近真正的 AI SaaS 产品。

## 最关键的一个选择

如果你现在问我：

> **主后端到底 Java 还是 Go？**

我建议你这个项目：

### 主后端

**Spring Boot**

### 辅助高并发服务

**Go**

### AI

先：

**Spring AI**

再：

**Python / FastAPI**

### 前端

**Next.js**

也就是：

```
        Next.js
           │
           ▼
      Spring Boot
      核心业务层
           │
 ┌─────────┼─────────┐
 │         │         │
 ▼         ▼         ▼
Postgres Redis     Kafka
 │
 ▼
pgvector

     ↓ 后期

Go
实时 / Worker / Gateway

Python
AI / Agent / RAG
```

这套项目架构尤其适合你，因为你已经学过 Java 和 Go，没必要再用项目证明“我会写 Java CRUD”“我会写 Go CRUD”；真正值得练的是：

> **什么时候应该使用 Java，什么时候应该使用 Go，什么时候应该引入 Python，以及不同技术如何组成一个真实系统。** 

如果你准备正式开始这个项目，我下一步最建议直接帮你定下来 **DevLab V1 的完整需求、数据库表、Spring Boot 模块结构、Next.js 目录结构、API 列表和第一阶段开发顺序**，这样你可以直接开仓库开始写。
